# Open work

Every open item carries a stable id (V vocabulary, R rows, C composition, S sessions, B view boundary, F formatting, P parity, D decisions, O ownership, X platform, G guidance) and a size (**S**/**M**/**L**). Contracts are in [ARCHITECTURE.md](ARCHITECTURE.md). **Delete an item's line in the commit that lands it** — ids are never reused.

One item, one commit, both apps built and tested. Core rule + test, regenerate bindings, delete the app code it replaced on both sides, clear that screen's view leak while you are in it.

## 7. Everything else

Product or security decisions, one question each:

- **D1** Biometric gate — iOS prompts on every secret read via the [Keychain](../ios/Packages/Keychain/Sources/Keychain.swift) ACL; Android prompts per call site and [`TinkGemPreferences`](../android/app/src/main/kotlin/com/gemwallet/android/data/password/TinkGemPreferences.kt) is unauthenticated, so a new caller bypasses it. Core should mark which operations need authentication.
- **D2** Notification permission — Core's [`notification_prompt`](../core/gemstone/src/services/preferences/rules.rs) now tells never-asked from denied and Android requests through an activity collector, but the [adapter](../android/data/services/gemstone/src/main/kotlin/com/gemwallet/android/data/services/gemstone/notifications/NotificationPermissions.kt) still takes an application context from [`BannersModule`](../android/data/services/gemstone/src/main/kotlin/com/gemwallet/android/data/services/gemstone/di/BannersModule.kt) for `isGranted` and `openSettings`.
- **D3** Privacy lock — iOS has [one](../ios/Features/LockManager/Sources/), Android none. Product call.
- **D4** WalletConnect one-click auth — Android only, rules live in [`WCAuthViewModel`](../android/features/bridge/viewmodels/src/main/kotlin/com/gemwallet/android/features/bridge/viewmodels/WCAuthViewModel.kt). Product call.
- **D5** Earn — both apps have the surface (Android's landed 2026-09-12) and both go through the amount service; `EARN_OFFERED` in [`config/stake.rs`](../core/gemstone/src/config/stake.rs) keeps it hidden. Product call to turn it on.
- **D6** Universal links — [DEEPLINKS.md](DEEPLINKS.md) says `/perpetuals` and `/rewards` are not iOS Universal Links and the [Android manifest](../android/app/src/main/AndroidManifest.xml) does not declare `/rewards`; the AASA is server-side. Decide the paths, then declare them on both.
- **D7** WalletConnect Bitcoin — [FEATURES.md](FEATURES.md) marks `bip122` as unimplemented in the [request handler](../core/crates/gem_wallet_connect/src/request_handler/mod.rs) and says the session advertises `eth_sendRawTransaction` while the handler rejects it; [`signAllTransactions`](../core/gemstone/src/services/wallet_connect/mod.rs) with more than one transaction is rejected too. Product call on the method set.
- **D8** Keystore v4 follow-ups from [KEYSTORE_V4.md](KEYSTORE_V4.md): whether migration failures need durable telemetry or user-visible recovery, and the synchronous [`Keystore` trait](../core/crates/gem_keystore/src/storage/secret.rs) that a browser backend would need an in-memory mirror for.
- **D10** Price freshness has no floor on the wallet screen — the asset, transactions and perpetuals screens fall back to Core's `refresh_interval`, the [wallet home](../ios/Features/WalletTab/Sources/Scenes/WalletScene.swift) has no timer and takes prices only from the socket, so a stream that stops delivering leaves the main screen stale with no signal. Decide whether the home takes the same safety net or whether stream health drives the fallback.
- **D9** Swap max-amount fee trim — [SWAPPER.md](SWAPPER.md) records that confirmed and signed amounts can differ by up to the fee on providers outside the [reserve rule](../core/crates/swapper/src/fees/reserve.rs). Decide whether the signer or the quote owns the trim.
